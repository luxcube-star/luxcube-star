# 2026-11-20 모아+ 추천 처음 맞추기 자리 확인

1. 사용자 사진 두 장(1:25 처음 맞추기 · 카카오톡 입력) 「높이가 이젠 맞는 거 같아」 → 97f8ea7(41pt 고정) 설치됨. 원본 픽셀(1290×2796)로 잼: 키보드 바탕 1671~2570px · 다섯 줄 위치(1804 · 1958 · 2111 · 2265 · 2418px 시작, 각 140px)가 두 사진에서 1px 도 다르지 않음 → 처음 맞추기 키보드가 실제 키보드와 같은 자리 · 크기. 현황 노트 남은 확인 ① 다섯 줄 높이 · ② 처음 맞추기 자리 끝남 · ③ 「화면아래까지」는 「모름」(41pt 고정으로 대신함)
2. 사용자 「단어와 문장 추천이 생각한 것과 같이 제대로 작동하지 않아. 추천 알고리즘이나 규칙을 다시 검색해 줘」 → 고친 질문 · 여쭘(1 예 · 2 문장 뜻 · 3 범위 · 4 꼴) → 사용자 「3가 4가부터」 = 바깥 자료 조사 · 대화창 요약
3. 바깥 자료 조사 요약(근거 링크는 대화창): ① 상용 키보드는 미리 만든 일반 언어 모델 + 사용자 모델을 섞어(보간) 순위 — 사용자 글이 적을 때 일반 모델 몫이 큼(Google 43272 · Adhikary/Vertanen · 특허). 새모아는 일반 사전 없이 사용자 학습만 + 2번 문턱 ② 다음 단어는 n-gram 물러서기(Stupid Backoff 0.4배) ③ 최근성 지수 감쇠(Presage) · 쓰면 올리고 정리 때 내림(LatinIME) ④ LatinIME 사용자 단어 짝 6번 문턱을 없애 바로 쓰게 바꾼 커밋 · 옛 코드는 고른 단어 3 · 친 단어 1 ⑤ 한국어는 어절 꼴이 많아 형태소 · 음절 단위 모델(삼성 Yu 2017 휴대폰 배포 · 삼성 어절 추천 특허) ⑥ 구절: 단어 후보마다 그 단어로 시작하는 구절(Arnold 2016) · Gmail Smart Compose 는 확신 문턱 넘을 때만 ⑦ 평가는 키 입력 절약률(이송욱 2015). 새모아 리포트 11-17: 보여 줌 4242 · 고름 147(약 3.5%) · 아낀 글자 421
4. 사용자 「검색한 것만 가지고 새 알고리즘을 구성해서 알려 줘」 → 9단계 안(Stupid Backoff · 감쇠 · 고른 단어 3배 · 문턱 · 일반 사전 섞기 · 구절 확신 문턱 · 조사 · 절약률)과 정할 것 1~4 여쭘 → 「추천해 줘」 → 1 나(두 번 그대로) · 2 나(일반 사전 빼기 — 못 구함 · 메모리) · 3 다(문턱 없이 두고 리포트에 구절 보여 줌 · 고름을 세어 정함 — 앞서 보기 가 「학습 파일 통계」는 파일이 아이폰에만 있어 Claude 가 못 봄, 바로잡음) · 4 가
5. 사용자 「구현해」(= 추천대로) → 만듦: PredictionEngine — 다음 단어 · 단어 완성 순위를 한 점수로(앞 두 단어 비율 → 0.4 × 앞 한 단어 비율 → 단어 완성만 0.16 × 단어 자체 감쇠 비율; 같은 점수면 감쇠 점수 아주 작게) · 예전 고정 가산점 · 칸 나누기 없앰 · learn(accepted:) 고른 단어 점수 +3(쓴 횟수 +1) · 통계 typedCharacters · rateSavedCharacters · phraseShown · phraseAccepted(decodeIfPresent, 판 그대로 4) · 리포트 줄에 절약률 · 구절 보여 줌 · 고름. 뷰모델 — 고른 단어를 기억해 보류 단어가 그것이면 accepted · 고른 구절 안쪽 단어도 accepted · recordShown(includesPhrase:).
